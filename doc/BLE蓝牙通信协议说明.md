## 2. 综述

该协议规定了BMS电池管理系统与手机蓝牙之间数据交互的流程、格式和内容。通过蓝牙连接，手机端可以读取电池基本信息、SOH、历史记录，并执行 OTA 升级与保护参数设置。

---

## 3. 通信规约

BMS和手机蓝牙采用主从机制，一问一答，手机为主，BMS为从。主机读取时直接发送对应的功能码，不带数据块。

### 3.1 BLE GATT 与编码

| 项目 | 说明 |
|------|------|
| **接收（手机侧收数）** | 使用 **FFF1** 服务/特征（UUID 短形式 `0xFFF1`）。手机端须对该特征 **启用 Notify（通知）** 后，方可接收从机上报的协议帧。 |
| **发送（手机侧发数）** | 使用 **FFF2** 服务/特征（UUID 短形式 `0xFFF2`）。主机通过 **Write** 向从机下发指令帧。 |
| **字符编码** | 协议中涉及文本的字段统一采用 **GB18030** 编码（与 ASCII 兼容的字符编码结果与 ASCII 一致）。 |

> **说明：** 不同蓝牙模块对「服务」与「特征」的文档表述可能不同；若模块将 `0xFFF1` / `0xFFF2` 挂在同一自定义服务下，请以模块厂商说明为准，本协议以 **接收走 FFF1 + Notify、发送走 FFF2** 为准。

## 4. 主协议格式

| 起始位（1 Byte） | 功能码（2 Byte） | 数据长度（2 Byte） | 数据块（N Byte） | XOR校验值（2 Byte） | 结束位（2 Byte） |
|:-:|:-:|:-:|:-:|:-:|:-:|
| 帧头 0x55 | 功能码用于区分当前指令功能 | 数据块的长度 | 数据内容 | 对起始位、功能码、数据长度、数据块所有字节进行异或操作 | 帧尾 0xAABB |

**说明：**
- 多字节字段均采用**大端**字节序（高字节在前）
- XOR校验范围：起始位 + 功能码 + 数据长度 + 数据块，逐字节异或
- 数据长度为数据块的实际字节数

## 6. 协议信息

### 功能码 - 查询电池信息：0x1001

用于读取BMS电池管理系统的基本信息，包括电压、电流、温度、SOC、故障状态、保护参数等。

#### 主机发送

主机发送查询命令时，数据块为空（数据长度 = 0）。

| 字段 | 长度 | 内容 |
|------|------|------|
| 无 | - | - |

#### 从机回复

| 序号 | 字段 | 长度 | 单位/说明 |
|:----:|------|:----:|-----------|
| 1 | 设备序列号 | 16 Byte | ASCII码格式，不足16字节补0x00 |
| 2 | 总电压 | 2 Byte | Unit: 0.1V，小端 |
| 3 | 电流 | 2 Byte | Unit: 0.1A，有符号，小端（正值为充电，负值为放电） |
| 4 | SOC | 1 Byte | Unit: 1%，范围 0~100 |
| 5 | 电池工作状态 | 1 Byte | 0x00: 待机<br>0x01: 充电中<br>0x02: 放电中 |
| 6 | 最高单体电压 | 2 Byte | Unit: mV，小端 |
| 7 | 最低单体电压 | 2 Byte | Unit: mV，小端 |
| 8 | 最高温度 | 1 Byte | Unit: 1°C，Offset: +40（实际温度 = 传输值 - 40） |
| 9 | 最低温度 | 1 Byte | Unit: 1°C，Offset: +40（实际温度 = 传输值 - 40） |
| 10 | MOS温度 | 1 Byte | Unit: 1°C，Offset: +40（实际温度 = 传输值 - 40） |
| 11 | 剩余容量 | 2 Byte | Unit: 10mAh，小端 |
| 12 | 额定容量 | 2 Byte | Unit: 0.1Ah，小端 |
| 13 | 循环次数 | 2 Byte | 小端 |
| 14 | 电芯串数 | 1 Byte | 电池包串联电芯数量 |
| 15 | 开关信号状态 | 1 Byte | Bit 0: 充电MOS（1=导通, 0=断开）<br>Bit 1: 放电MOS（1=导通, 0=断开）<br>Bit 2: 预放MOS（1=导通, 0=断开）<br>Bit 3~7: 保留 |
| 16 | 故障标志位 | 4 Byte | 小端，详见故障标志位定义 |
| 17 | 一级放电过流保护值 | 2 Byte | Unit: 0.1A，小端 |
| 18 | 充电过流保护值 | 2 Byte | Unit: 0.1A，小端 |
| 19 | 单体过压保护电压 | 2 Byte | Unit: mV，小端 |
| 20 | 单体过放保护电压 | 2 Byte | Unit: mV，小端 |
| 21 | 充电高温保护值 | 1 Byte | Unit: 1°C，Offset: +40 |
| 22 | 放电高温保护值 | 1 Byte | Unit: 1°C，Offset: +40 |
| 23 | 最大允许充电电流 | 2 Byte | Unit: 0.1A，小端 |
| 24 | 最大允许放电电流 | 2 Byte | Unit: 0.1A，小端 |
| 25 | 硬件版本 | 1 Byte | 从0x01开始 |
| 26 | 软件版本 | 1 Byte | 从0x01开始 |
| 27 | 产品线 ID 长度 | 1 Byte | `N`；`0` 表示无扩展（旧固件，最小数据块 52 字节） |
| 28 | 产品线 ID | N Byte | ASCII，与升级服务器 `product_id` 完全一致，如 `7240_Public`、`9645_FeiShen`；建议 N ≤ 32 |

**扩展字段说明：**

- 数据块最小长度仍为 **52 字节**（字段 1~26）；字段 27~28 为可选扩展。
- **固件版本号不单独传输**，由字段 25、26 按下列规则拼接后与升级服务器 `version` / `latest_version` 比较：
  - 将硬件版本号、软件版本号各按 **1 字节十进制数值格式化为 2 位字符**（不足 2 位前补 `0`），再前后拼接（非按字节转十六进制字符串）。
  - 示例：硬件版本 `0x01`、软件版本 `0x0C`（即版本 12）→ **`0112`**；硬件 `0x01`、软件 `0x11`（即版本 17）→ **`0117`**；硬件 `0x10`、软件 `0x11` → **`1617`**。
- 产品线 ID 采用「1 字节长度 + ASCII 内容」；长度非法或超出缓冲区时，上位机应忽略扩展字段。

用于设置BMS的保护参数，支持设置一级放电过流保护值和充电过流保护值。

#### 主机发送

| 字段 | 长度 | 内容 |

**参数类型与范围说明：**

| 参数类型 | 描述 | 单位 | 范围说明 |
|:--------:|------|:----:|----------|
| 0x00 | 一级放电过流保护值 | 0.1A | 不低于放电过流保护下限，不高于放电过流保护上限 |
| 0x01 | 充电过流保护值 | 0.1A | 不低于充电过流保护下限，不高于充电过流保护上限 |

#### 从机回复

| 字段 | 长度 | 内容 |

### 功能码 - 读取历史记录：0x1004

用于分页读取历史采样记录。

#### 主机发送

| 字段 | 长度 | 单位/说明 |
|------|------|-----------|
| 起始索引 startIndex | 2 Byte | 小端，从 0 开始 |
| 读取条数 count | 2 Byte | 小端，建议 1~32 |

#### 从机回复

返回 N 条定长记录（N 由实际返回长度决定）。

**单条历史记录格式（16 Byte）：**

| 序号 | 字段 | 长度 | 单位/说明 |
|:----:|------|:----:|-----------|
| 1 | 时间戳 unixTime | 4 Byte | 小端，Unix时间戳（秒） |
| 2 | 总电压 | 2 Byte | Unit: 0.1V，小端 |
| 3 | 电流 | 2 Byte | Unit: 0.1A，有符号，小端 |
| 4 | SOC | 1 Byte | Unit: 1%，范围 0~100 |
| 5 | 预留 | 7 Byte | 预留，当前填 0x00 |

> 说明：若后续固件调整历史记录字段，仅需同步更新本节与上位机解析实现。

#### 从机回复

### 功能码 - OTA 数据分片：0x1006

用于发送 OTA 固件分片数据。

#### 主机发送

| 字段 | 长度 | 单位/说明 |
|------|------|-----------|
| offset | 4 Byte | 小端，分片起始偏移 |
| chunkLen | 2 Byte | 小端，分片长度 |
| chunkData | N Byte | 固件分片数据 |

#### 从机回复

| 字段 | 长度 | 单位/说明 |
|------|------|-----------|
| 状态码 | 1 Byte | 0x00: 成功；0x01: 请求重发；其他: 失败错误码 |
| 期望 offset（仅状态码=0x01 时） | 4 Byte | 小端，BMS 期望接收的下一个 offset |

**说明：**
- 当状态码为 `0x00` 时，数据块长度为 1 字节（仅状态码）
- 当状态码为 `0x01` 时，数据块长度为 5 字节（状态码 + 期望 offset）
  - BMS 检测到丢包时，会在响应中携带期望接收的 offset
  - 手机侧收到后应回退到该 offset 重传
  - 若期望 offset = 当前 offset，说明当前包损坏，重发当前包即可

---

## 7. 通信示例

### 示例1：查询电池信息

**主机发送（查询命令）：**

```
55 10 01 00 00 [XOR_H] [XOR_L] AA BB
```

| 字节 | 说明 |
|------|------|
| 0x55 | 帧头 |
| 0x10 0x01 | 功能码 0x1001（查询电池信息） |
| 0x00 0x00 | 数据长度 = 0 |
| [XOR] | 2字节XOR校验 |
| 0xAA 0xBB | 帧尾 |

**从机回复：**

```
55 10 01 [LEN_H] [LEN_L] [数据块...] [XOR_H] [XOR_L] AA BB
```

### 示例2：设置一级放电过流保护值为60A

**主机发送：**

```
55 10 02 00 03 00 58 02 [XOR_H] [XOR_L] AA BB
```

| 字节 | 说明 |
|------|------|
| 0x55 | 帧头 |
| 0x10 0x02 | 功能码 0x1002（设置保护参数） |
| 0x00 0x03 | 数据长度 = 3 |
| 0x00 | 参数类型 = 0x00（一级放电过流保护值） |
| 0x58 0x02 | 参数值 = 0x0258 = 600（小端），即 600 × 0.1A = 60A |
| [XOR] | 2字节XOR校验 |
| 0xAA 0xBB | 帧尾 |

**从机回复（设置成功）：**

```
55 10 02 00 01 01 [XOR_H] [XOR_L] AA BB
```

### 示例3：设置充电过流保护值为15A

**主机发送：**

```
55 10 02 00 03 01 96 00 [XOR_H] [XOR_L] AA BB
```

| 字节 | 说明 |
|------|------|
| 0x55 | 帧头 |
| 0x10 0x02 | 功能码 0x1002（设置保护参数） |
| 0x00 0x03 | 数据长度 = 3 |
| 0x01 | 参数类型 = 0x01（充电过流保护值） |
| 0x96 0x00 | 参数值 = 0x0096 = 150（小端），即 150 × 0.1A = 15A |
| [XOR] | 2字节XOR校验 |
| 0xAA 0xBB | 帧尾 |

### 示例4：查询 SOH

**主机发送：**

```
55 10 03 00 00 [XOR_H] [XOR_L] AA BB
```

**从机回复（示例：SOH=95%）：**

```
55 10 03 00 01 5F [XOR_H] [XOR_L] AA BB
```

### 示例5：读取历史记录（从索引0读取32条）

**主机发送：**

```
55 10 04 00 04 00 00 20 00 [XOR_H] [XOR_L] AA BB
```

**从机回复：**

```
55 10 04 [LEN_H] [LEN_L] [历史记录块...] [XOR_H] [XOR_L] AA BB
```

### 示例6：OTA开始（镜像大小 0x0001F400，CRC32 0x89ABCDEF）

**主机发送：**

```
55 10 05 00 08 00 F4 01 00 EF CD AB 89 [XOR_H] [XOR_L] AA BB
```

**从机回复（开始成功）：**

```
55 10 05 00 01 00 [XOR_H] [XOR_L] AA BB
```

### 示例7：OTA数据分片（offset=0，长度=4，数据=11 22 33 44）

**主机发送：**

```
55 10 06 00 0A 00 00 00 00 04 00 11 22 33 44 [XOR_H] [XOR_L] AA BB
```

**从机回复（示例：请求重发，期望 offset=0x0000）：**

```
55 10 06 00 05 01 00 00 00 00 [XOR_H] [XOR_L] AA BB
```

| 字节 | 说明 |
|------|------|
| 0x01 | 状态码 = 0x01（请求重发） |
| 0x00 0x00 0x00 0x00 | 期望 offset = 0（小端） |

**从机回复（示例：成功）：**

```
55 10 06 00 01 00 [XOR_H] [XOR_L] AA BB
```

### 示例8：OTA结束

**主机发送：**

```
55 10 07 00 01 01 [XOR_H] [XOR_L] AA BB
```

**从机回复（结束成功）：**

```
55 10 07 00 01 00 [XOR_H] [XOR_L] AA BB
```

## 8. 注意事项

1. **主从机制**：手机为主机，BMS为从机，所有通信由手机发起
2. **一问一答**：主机发送一条指令后，需等待从机回复后再发送下一条指令
3. **XOR校验**：校验范围包括起始位、功能码、数据长度和数据块的所有字节，逐字节异或，结果为2字节
4. **温度偏移**：所有温度数据均有 +40 偏移，实际温度 = 传输值 - 40
5. **参数范围**：设置保护参数时，参数值必须在有效范围内，否则BMS将返回设置失败
6. **参数保存**：修改保护参数后会自动保存到Flash，重启后生效
7. **字节序**：多字节数据字段采用小端格式（低字节在前）
8. **BLE 与编码**：手机端须对 FFF1 开启 Notify 后再收数，向 FFF2 写指令发数；文本字段编码见第 3.1 节（GB18030）
9. **历史记录分页**：建议单次 `count <= 32`，上位机按返回条数递增 `startIndex`
10. **OTA串行发送**：严格一问一答，上一分片收到应答后再发送下一分片
11. **OTA期间轮询控制**：OTA开始后应暂停周期性 `0x1001` 查询，OTA结束后恢复
12. **OTA分片长度**：受 BLE MTU 限制，建议按协商 MTU 扣除协议开销后设置（推荐 128 Byte 起）
13. **OTA丢包重传**：当 BMS 检测到序号跳跃（丢包）时，会在 RESEND 响应中携带期望的 offset，手机侧应回退到该位置重传，而不是继续发送当前位置的数据
14. **OTA 产品线**：升级前须从 0x1001 读取产品线 ID，并由字段 25/26 拼接固件版本号，与升级服务器 `battery_update` 的 key 及 `latest_version` 匹配后再下载固件
